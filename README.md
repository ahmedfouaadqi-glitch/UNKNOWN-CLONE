# UNKNOWN — غير معروف

A bilingual global anonymous expression platform.

**Tagline (AR):** قل ما بداخلك، دون أن تكشف من أنت.  
**Tagline (EN):** Say what you feel. Stay unnamed.

## Product principles

- Public posts and anonymous comments; no account or public profile required.
- Search stories by Arabic/English text and category, with paginated latest and category feeds.
- Arabic and English at launch, with country-aware welcome and locale defaults.
- Approximate country detection from trusted edge headers only; no GPS permission.
- White daytime / black nighttime theme.
- Original pencil-line SVG identity (wordmark, logo mark and favicon), plus PNG app and Apple touch icons generated by Next.js.
- Story search by Arabic/English text and category; paginated public feeds.
- Respectful interaction, content safety, reporting and deletion. Moderator case management and the appeal submission/review lifecycle are not yet operational.
- No public dashboard, follower graph, direct messages or behavioral advertising.

## Technology

- Next.js 16.4.3 (Active LTS at project bootstrap), React 19.3.1, TypeScript 5.9.3.
- Tailwind CSS 4.3.3.
- Supabase PostgreSQL via a server-only service client.
- Native SVG identity assets and custom CSS motion; ReactBits-inspired interaction patterns are implemented locally rather than loading a third-party runtime.

## Local development

Requires Node.js 22.16 or later.

```bash
cp .env.example .env.local
npm install
npm run dev
```

The public site renders without database credentials. Publishing, comments, reactions and reports return a clear configuration error until the dedicated Supabase project is configured.

## Supabase setup

1. Create a **dedicated** Supabase project for UNKNOWN. Do not reuse the unrelated projects in the connected account.
2. Copy the project URL and the server-only service-role key to `.env.local`.
3. Run `supabase/migrations/20261101000100_unknown_init.sql` in the Supabase SQL editor or through the Supabase CLI.
4. Keep the service-role key server-side only. Never create a `NEXT_PUBLIC_*` variable for it.
5. The migration enables RLS on every public table, grants no public table access, and grants the server role the required privileges. Server API handlers return only approved public fields.
6. Configure the public schema in Data API settings if the project has schema exposure disabled. Supabase changed default exposure behavior for new tables in 2026; verify the project setting before relying on PostgREST.
7. Set a strong `RATE_LIMIT_SECRET` and apply CDN/WAF request limits before public launch.

## Important launch limitations

The repository contains published operating policies and official legal-source links; these do not by themselves constitute regulatory approval or a declaration of worldwide legal compliance.

- Public-facing terms, privacy notice, publishing disclaimer and community rules are published in Arabic and English. Publication of these policies does not itself certify worldwide legal compliance or regulatory approval.
- The legal center links to official legislative and regulatory sources for Iraq, the EU, the UK, the US, Canada, Australia, Brazil, India and Japan; consultation materials are labelled separately from enacted rules.
- The operator identity and supplied email/phone are published. A full street address, production domain, infrastructure-provider list and exact retention periods are still to be configured.
- Iraq: obtain written CMC classification and resolve any applicable notification, registration or licence under Articles 4–5 of the Framework Regulations before enabling UGC publishing. Article 6.1.2 also covers review, human oversight and appeals for covered UGC providers.
- The moderation rules are a conservative first-pass filter, not a guarantee that all abuse, defamation, threats or personal data will be detected. A staffed escalation path and market-specific compliance review are required where law requires human oversight.
- Age confirmation is not identity or age verification. Where a law requires stronger age assurance, the corresponding age-related controls must be applied even though the market is not pre-emptively geo-blocked.
- GeoIP is approximate and never proves nationality, residence or legal jurisdiction.
- The project intentionally contains no admin dashboard. Restricted reports and moderation cases require a documented, least-privilege operational process.

## Contact configuration

The public contact page displays only verified operator-owned addresses and links configured through the variables in `.env.example`. Unconfigured addresses and placeholder social accounts are not shown.


## Global availability policy

The site is globally available by default. Country-level blocks are not applied pre-emptively merely because a jurisdiction appears in the legal-source register. Directly applicable legal obligations remain in force regardless of whether an authority has sent a notice. See `docs/launch-gates.md` and `docs/official-restriction-requests.md` for the legal request and restriction procedure.
